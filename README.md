# SEO・AIO マイスター

サイトが検索と AI の回答で引用されるまでを、1 体で通して受け持つ Agent です。
事業を調べ、サイトを整え、戦略を決め、書くべき問いを選び、記事を書き、確かめ、結果を測って戦略を直します。

記事を書くことと、その記事を確かめて通すことは、必ず別の Session で行います。書いた本人がその場で通すと、誤りを見落とすためです。

## できること

| 段階 | すること |
|---|---|
| 0. 準備 | サイトの URL、対象の国と言語、記事の置き場所、書き手、データ源がそろっているかを確かめます。足りないデータ源は、つなぐ手順を渡します |
| 1. 事業調査 | サイト・資料・Web から、事業・顧客・競合・自社だけの根拠を整理します。足りないことは Ask で聞きます |
| 2. サイト整備 | 検索と AI のクローラーが読める状態か、記事の体裁が整っているかを調べ、直すことの一覧を作ります |
| 3. 戦略 | 狙うテーマ 3〜5 本と記事の組み方を決め、承認を求めます |
| 4. キーワード選定 | 承認された戦略の中から問いを選びます。検索数、買う気の強さ（クリック単価）、検索上位と AI による概要の現状、勝てる理由を付けます |
| 5. 記事作成 | 選んだ問いを根拠つきの概要にし、その概要から原稿を書いて、サイトの repo の作業ブランチに置きます。事業の概要に無い数字や実績は書きません |
| 6. 受け入れ確認 | 原稿を、概要・事実・引用されやすさの観点で確かめ、通すか戻すかを決めます。書いた Session とは別の Session で行います |
| 7. 効果測定 | 公開した記事の表示・順位と、AI による概要での引用を追い、直す記事と戦略の変更を提案します |

検索数が多い語ではなく、「この会社だから答えられる問い」を選びます。

状況と数字は、Project HTML の画面（`seo-dashboard.html`）で見られます。検索の実績の推移、キーワードの候補、AI による概要に引用されているサイト、サイトの対応状況が、グラフで並びます。

検索数、クリック単価、問いごとの検索結果と引用元、Search Console の日ごとの数字、使った額は、Project のデータベースにためます。取った数字が消えず、同じ語を取り直さずに済み、画面はデータベースを直接読みます。データベースが使えない Project では、文書に残す形で動きます。

## 測れること、測れないこと

| | 測れるか | 要るもの |
|---|---|---|
| 自社サイトの表示回数・クリック・順位 | 測れる | Search Console（無料） |
| 任意の問いの検索数と推移 | 測れる | DataForSEO、ラッコキーワード、Ahrefs のどれか |
| 買う気の強さ（検索広告のクリック単価） | 測れる | DataForSEO |
| Google の「AI による概要」に、問いごとに誰が引用されているか | 測れる | DataForSEO |
| ChatGPT・Perplexity などから来た訪問の数 | 測れる | Google アナリティクス 4（無料） |
| ChatGPT・Perplexity などの回答が、どの問いで自社を引用したか | **測れない** | — |
| Bing の検索の数字 | **測れない** | — |

データ源が何も無くても動きますが、検索数は推測に、AI による概要の引用は「未確認」になります。問いごとの引用を追うには DataForSEO が要ります。

## 準備するもの

| もの | 必須か | 用途 |
|---|---|---|
| サイトの URL と、対象の国・言語 | 必須 | 検索数と引用を、正しい国で取る。最初の依頼で聞かれます |
| Web 検索ができる実行環境 | 必須 | 競合・顧客の言葉・検索上位の調査 |
| サイトの repo を Project の repository に設定 | 推奨 | 製品の説明と既存の記事を読み、原稿を作業ブランチに置く。無ければ、原稿は Project の文書に置きます |
| Search Console の読み取り権限 | 任意・無料 | 自社サイトが表示された問いの実数と順位を取る |
| Google アナリティクス 4 の読み取り権限 | 任意・無料 | 記事に来た人が問い合わせや申し込みに進んだか、AI のサービスから人が来たかを見る |
| 検索数のツールのキー（下の 3 つから 1 つ） | 任意・有料 | どの問いでも、検索数と推移を取る |

実行環境には `python3`、`openssl`、`curl` が要ります。

スクリプトの既定は日本・日本語です。ほかの国や言語のサイトでは、最初の準備で値を決め、Agent が呼ぶたびに渡します。日本以外での動作は、まだ十分に試していません。

### 記事を書くのは誰か

何も決めなければ、この Agent が自分で書きます。原稿は作業ブランチ（設定によっては PR）に置き、公開用のブランチには入れません。公開するかどうかは人間が決めます。

書き手を変えることもできます。別の Agent、記事作成の Workflow、人間のどれでもかまいません。最初の準備のときに伝えてください。その場合、この Agent は概要（Project 文書 `docs/briefs/`）を渡すところまでを行い、戻った原稿を受け入れ確認します。

### 検索数のツールを選ぶ

1 つあれば足ります。複数を登録したときは、表の上から順に 1 つだけ使います。

| ツール | 向いている場合 | 費用の形 | 登録する Secret |
|---|---|---|---|
| DataForSEO | 迷ったらこれ。検索数、クリック単価、問いごとの AI による概要の引用元が、1 つの契約で取れる。国と言語を選ばない | 使った分だけ（前払い） | `DATAFORSEO_LOGIN`、`DATAFORSEO_PASSWORD` |
| ラッコキーワード | 日本語のサイトで、質問文をまとめて集めたい。自社や競合のドメインが AI による概要に載っている問いを調べたい | 月額＋クレジット | `RAKKO_API_KEY` |
| Ahrefs | 既に Ahrefs を契約している。難易度も見たい | 月額＋月ごとの単位 | `AHREFS_API_KEY` |

Tools > Secrets で登録し、この Agent に使用を許可します。キーは自分で契約したものを使ってください。料金と、API が使えるプランは、各社の公式の案内で確かめてください。

DataForSEO と Search Console は本物の鍵で動作を確かめています。ラッコキーワード、Ahrefs、Google アナリティクス 4 は、公式の仕様に合わせて作ってありますが、本物の鍵ではまだ試していません。

### Search Console と Google アナリティクス 4 をつなぐ

鍵は 1 つで、両方に使えます。片方だけでも動きます。

1. Google Cloud で「Search Console API」と「Google Analytics Data API」を有効にし、サービスアカウントを作って JSON の鍵を発行する。
2. Search Console の「設定 > ユーザーと権限」で、サービスアカウントのメールアドレスを「制限付き」で追加する。
3. GA4 の「管理 > プロパティのアクセス管理」で、同じメールアドレスを「閲覧者」で追加する。
4. Tools > Secrets で次を登録し、この Agent に使用を許可する。
   - `GOOGLE_SERVICE_ACCOUNT_JSON`: 鍵の JSON の中身。1 行しか入らない欄なら base64 にしたものでもよい。
   - `GSC_SITE_URL`: Search Console のプロパティ。ドメインなら `sc-domain:example.com`、URL なら `https://example.com/`。
   - `GA4_PROPERTY_ID`: GA4 のプロパティ ID（数字だけ。`G-` で始まる測定 ID ではない）。

どれをつなぐか迷ったら、Agent に「分析ツールの連携を進めてください」と頼んでください。今の状況でいちばん効くものを 1 つ勧め、手順を渡し、つながったかを確かめます。

## 使い方

Project に参加させて、依頼します。今どの段階かは Agent が Project の文書から判断します。

**最初に（準備と戦略）**

```text
このサイト（https://example.com、日本・日本語）について、準備を確かめて、事業を調べてキーワード戦略を作ってください。
```

事業について 3〜5 問の Ask が届きます。答えると戦略の案が届くので、承認するか、直したい点を返してください。

**サイトを整える**

```text
サイトが検索と AI に読まれる状態か、調べてください。
```

**繰り返し（キーワードを選んで、記事を書く）**

```text
キーワードを 1 つ選んで、概要を作り、記事の原稿を書いてください。料金のかかる呼び出しは 1 ドルまでにしてください。
```

最初に書く記事は、Ask で承認を求められます。原稿は作業ブランチに置かれ、報告に「人間に確かめること」が付きます。

**原稿ができたら（受け入れ確認。新しい Session で頼みます）**

```text
〈ブランチや PR〉の記事を、公開する前に確かめてください。
```

書くことと確かめることを自動でつなぎたいときは、この 2 つの依頼を Workflow の 2 つの段にします。

**4 週間に 1 回（効果測定）**

```text
公開した記事の結果と、AI での見え方を見て、次の手を提案してください。
```

**いつでも（画面を見る）**

```text
ダッシュボードを更新してください。
```

## 作るもの

すべて Project の文書です。この repo には書きません。

| 文書 | 場所 |
|---|---|
| 設定（サイトの URL、国と言語、書き手、データ源） | `docs/seo-settings.md` |
| 事業の概要 | `docs/business-profile.md` |
| サイトの受け皿 | `docs/site-readiness.md` |
| キーワード戦略 | `docs/keyword-strategy.md` |
| 候補の一覧と根拠 | `docs/keyword-candidates.md` |
| 記事の概要 | `docs/briefs/` |
| 記事の原稿 | サイトの repo の作業ブランチ（repo が無ければ `docs/drafts/`） |
| 選んだ問い・受け入れの判断・結果の記録 | `docs/seo-log.md` |
| AI での見え方 | `docs/ai-visibility-panel.md`、`docs/ai-visibility-log.md` |
| たまっていく数字（キーワード、検索結果と引用元、日ごとの検索の数字、使った額） | Project のデータベース（`seo_` で始まる 5 つの表） |
| 人間が見る画面 | Project HTML の `seo-dashboard.html` |

## 中身

- `identity.md`: 役割と、守ること
- `.agents/skills/`: 17 本
  - 進め方: `seo-aio-playbook`（一巡の段階、今どこにいるかの見分け方、文書の置き場所、判断の基準）
  - 準備: `seo-setup`、`seo-data-connect`
  - 土台: `seo-business-research`、`site-readiness-audit`
  - 戦略と企画: `keyword-strategy`、`keyword-discovery`、`keyword-evidence`、`ai-citation-check`
  - 記事: `article-brief`、`article-writing`、`article-acceptance-check`
  - 計測: `seo-results-review`、`ai-visibility-tracking`
  - 共通: `seo-data-sources`（データ源の選び方とスクリプト）、`seo-database`（数字を Project のデータベースにためる）、`seo-dashboard`（状況と数字を 1 枚の画面にする）
- `environment.yaml`: 実行環境と、任意の環境変数の宣言
- `knowledge/`: Agent が、会社をまたいで役に立つ学びを書き足す場所。最初は空です

会社ごとの情報はこの repo に置きません。
